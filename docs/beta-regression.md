# Beta regression compatibility and performance

## Statistical contract

`BetaRegression` implements classical maximum-likelihood beta regression for
responses strictly inside `(0, 1)`. It uses the mean/precision parameterization
of R's `betareg`, analytic scores, and the same expected Fisher information for
inference. Mean and precision can have distinct design matrices.

This does not claim compatibility with `betareg`'s extended-support,
bias-corrected, bias-reduced, mixture, or tree models.

Grouped and pedigree random effects are covered separately in the
[sparse beta mixed-model note](beta-mixed-models.md).

## Package-example accuracy

The comparison used `betareg` 3.2-6 under R 4.6.1 and the package's own
`GasolineYield` and `FoodExpenditure` data. Full-precision R values are
regenerated by
`src/test/resources/r-reference/generate-betareg-reference.R` and asserted by
`BetaRegressionRReferenceTest`.

| Example | Compared quantities | Maximum absolute difference |
| --- | --- | ---: |
| `yield ~ batch + temp` | 11 mean coefficients, precision, 12 SEs, log likelihood | below `2e-6` |
| `yield ~ batch + temp \| temp` | 11 mean coefficients, 2 precision coefficients, precision SEs, log likelihood | below `1e-7` except the temperature coefficient/SE below `2e-10` |
| `food/income ~ income + persons` | 3 mean coefficients, precision, 4 SEs, log likelihood | below `2e-7` |

Run the gate with:

```powershell
.\gradlew.bat test --tests org.jlinalg.distributional.BetaRegressionRReferenceTest
```

## Performance

The deterministic 100,000-observation benchmark has four mean coefficients
and two precision coefficients. Both implementations are warmed once and then
measured for five full fits. On the development host (Windows 11, Java 25,
R 4.6.1, `betareg` 3.2-6), the medians were:

| Runtime | Median fit time | Relative speed |
| --- | ---: | ---: |
| JLinAlg specialized beta regression | 143.216 ms | 14.59x |
| R `betareg` | 2,090 ms | 1.00x |

The specialized JLinAlg solver and the existing generic distributional solver
also agreed within `1.3e-14` on all coefficients. The specialized path was
1.29x faster than that generic Java path. JLinAlg and R agreed within
`2.6e-13` on the benchmark coefficients. These are workload- and host-specific
measurements, not universal guarantees.

Reproduce the Java and R sides with:

```powershell
.\gradlew.bat benchmarkBetaRegression
$env:JLINALG_BETA_R_LIBRARY = 'build/r-library'
& 'C:\Program Files\R\R-4.6.1\bin\Rscript.exe' `
  src/benchmark/r/beta_regression_benchmark.R
```
