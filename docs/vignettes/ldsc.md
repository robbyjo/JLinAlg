# Heritability and genetic correlation with LDSC

Source-build feature. Build with `./gradlew.bat executableJar` on Windows,
then run commands below from the repository root. Use fresh `.tsv` output
paths. The command creates an accompanying lifecycle log; `--log FILE` or
`--no-log` follows the other xWAS subcommands.

## Question and inputs

Estimate the genome-wide genetic variance of each trait and the genetic
covariance/correlation between traits. This is unpartitioned association
follow-up, independent of enrichment analysis.

`--input` is a CSV/TSV with one variant per row:

```text
variant  ea  oa  ld_score  weight_ld  z_A  n_A  z_B  n_B
rs1      A   C   12.5      6.2        2.1  10000 -1.3 12000
```

Use actual tabs or commas, unique variant IDs, and finite values. Identifiers
must be nonblank, unpadded, single-line and without quote characters. Every trait
z statistic must refer to the row's effect allele `ea` on the same forward
strand and genome build. The wide table is an explicit harmonization contract:
the command cannot infer an allele reversal inside an unlabeled z column.
Sample counts may vary across variants and traits. Use ancestry-compatible LD
scores and apply your prespecified summary QC before joining traits. This
version requires complete data for every requested trait.

`ld_score` sums LD over the reference variant set. `weight_ld` is the LD score
used for regression weighting, typically calculated over regression variants.
`--reference-variants` is the size M of the LD reference variant universe, not
the number of input rows. Supply variants in genomic order; the command divides
that order into equal contiguous jackknife blocks, differing by at most one row.
Choose enough blocks for uncertainty estimation and enough variants per block
to capture local LD. Tiny tutorial inputs do not establish genome-wide calibration.

## Run the checked-in example

```powershell
java -jar build/cli/jlinalg-0.3.5.jar ldsc --input examples/xwas/ldsc.tsv --traits A,B,C,D --reference-variants 100000 --blocks 30 --out build/xwas/ldsc.tsv
```

The synthetic example has 1,200 variants and four quantitative traits. Its
inputs and independent base-R QR reference are regenerated by
`src/test/resources/xwas/reference.R`. For one trait, use `--traits A`.

## Estimator and outputs

For each trait, regress `z^2` on `N * LD / M` with a free intercept. The slope
estimates observed-scale SNP heritability. For each trait pair, regress
`z_A * z_B` on `sqrt(N_A * N_B) * LD / M`; the slope estimates genetic covariance.
Weights combine the working Gaussian moment variance with inverse regression
LD score. There are two weight updates, then a final fit. Heritabilities are
clipped to [0,1] and covariances to [-1,1] only inside working weights; reported
estimates are not clipped.

The block jackknife holds final weights fixed. All trait pairs use the same
block deletions, supplying a full covariance matrix of their genetic moments.
For correlations, each deletion recomputes the ratio
`cov_g(A,B) / sqrt(h2_A*h2_B)`, so denominator uncertainty is included.

| Output | Meaning |
| --- | --- |
| `OUT` | Genetic moment estimate/SE/p, intercept/SE, genetic correlation/SE/p and status (unadjusted p-values) |
| `OUT.S.tsv` | Trait-by-trait genetic covariance S |
| `OUT.V.tsv` | Sampling covariance V of upper-triangle S entries, by rows |
| `OUT.intercepts.tsv` | Free intercept matrix on the z-product scale |
| `OUT.deletes.tsv` | Common delete-block genetic moments |
| `OUT.metadata.tsv` | Variant/block counts, M, estimator and scale |

For traits A,B,C, V labels are `A:A,A:B,A:C,B:B,B:C,C:C`. These files feed
[genomic-factor](genomic-factor.md) directly. Enough independent blocks are
needed for V to have full rank; the factor fitter rejects singular V.

Nonpositive heritability makes genetic correlation undefined. Nonpositive
delete-block heritability makes its jackknife SE unavailable. Such cases are
reported with NaN and explicit status. Correlations outside [-1,1] are flagged
and retained. An indefinite estimated S is not silently repaired.

## Java API and boundaries

```java
LdScoreRegression.Result fit = LdScoreRegression.fit(
    ldScores, regressionLdScores, zByVariantAndTrait,
    sampleSizesByVariantAndTrait, contiguousBlockIds, referenceVariantCount);
double[] geneticCovariance = fit.geneticCovariance();
double[] samplingCovariance = fit.samplingCovariance();
```

Import `org.jlinalg.xwas.LdScoreRegression`. Inputs are dense primitive arrays;
the CLI reads the input table in memory. Regression and block accumulation are
linear in variant count per trait pair; storing all z/N columns requires
O(variants × traits) memory. At most 32 traits are accepted.

This is the one-step, free-intercept, observed-scale estimator. It does not
calculate LD scores, perform summary munging, fit annotations, implement the
two-step intercept estimator, or convert binary traits to liability scale.
Variable-N weights use the supplied per-variant N in the stated moment model;
full numerical parity with every upstream LDSC option is not claimed.
Cross-trait intercepts are z-scale nuisance moments, not automatically a
trait-independent percentage of participant overlap.

Reference: [LDSC source and documentation](https://github.com/bulik/ldsc).
See [validation](../xwas-followup-validation.md) and continue to
[genetic factors](genomic-factor.md).
