# GRM construction: tutorial and Java vignette

The `grm` command constructs an additive genomic relationship matrix. The existing
`--grm` analysis option reads that matrix for Gaussian/non-Gaussian mixed models
or a Cox kinship frailty. Construction is new in source builds after v0.3.5;
build with `./gradlew executableJar` (Windows: `.\gradlew.bat executableJar`).

Read the [website version](https://robbyjo.github.io/JLinAlg/vignettes/grm.html)
for the same workflow with step-by-step navigation. Start with the small dosage
example below to understand filtering and matrix entries, then build a GRM from
VCF and use it in a mixed model. The [Java example](#java-vignette) uses the same
estimator without invoking the CLI.

## What the matrix represents

A GRM has one row and column per sample. It summarizes similarity in centered,
standardized additive genotypes. An LD matrix instead has rows and columns for
variants. In a Gaussian mixed model, a GRM can define the genetic covariance
component in `Var(y) = sigma_g^2 K + sigma_e^2 I`; the model estimates the variance
scales. Constructing `K` does not itself test association or estimate heritability.

Use a JDK 17 or newer and run from the repository root:

On Windows, use `.\gradlew.bat executableJar`. The examples refer to

## Step 2: inspect the genotype table

The supplied [dosages.tsv](../examples/grm/dosages.tsv) has four samples and five

| Variant | a | b | c | d |
|---|---:|---:|---:|---:|
| v1 | 0 | 1 | 2 | NA |
| v2 | 0 | 0 | 1 | 1 |
| monomorphic | 0 | 0 | 0 | 0 |
| low_call_rate | NA | NA | NA | 1 |
| v5 | 0 | 0 | 0 | 2 |

## Step 3: construct and inspect the GRM

This teaching example deliberately permits a call rate of 0.5 and MAF of zero
so that a retained missing call illustrates imputation. These are not proposed
production QC thresholds. Choose a fresh output path each time:

```shell
java -jar build/cli/jlinalg-0.3.5.jar grm --genotypes examples/grm/dosages.tsv --maf 0 --call-rate 0.5 --block-size 2 --backend cpu --out build/grm-tutorial/toy.tsv
```

The log `build/grm-tutorial/toy.tsv.log` reports five variants considered, three
used, and two excluded. The monomorphic variant has no allele variance; the
low-call-rate variant has only one of four samples called. For v1, the called
mean dosage is 1, so sample d is imputed to 1 and its standardized dosage is 0.

The resulting labeled matrix, rounded here to six decimals, is:

| sample | a | b | c | d |
|---|---:|---:|---:|---:|
| a | 1.111111 | 0.444444 | -0.666667 | -0.888889 |
| b | 0.444444 | 0.444444 | 0.000000 | -0.888889 |
| c | -0.666667 | 0.000000 | 1.111111 | -0.444444 |
| d | -0.888889 | -0.888889 | -0.444444 | 2.222222 |

Entries are additive relationships: `K(a,b)=4/9`, while the corresponding
kinship coefficient is `2/9`. Negative off-diagonal values can occur after
centering; they describe lower similarity relative to the allele-frequency
reference and should not be clipped to zero. Diagonals need not equal one.
This tiny synthetic matrix cannot establish pedigree categories or population
relatedness cutoffs. Its rows sum to zero because every retained dosage column
was centered on these samples, so singularity of this constructed matrix is
expected; a mixed model also includes its residual covariance component.

## Step 4: compare filtering choices

```shell
java -jar build/cli/jlinalg-0.3.5.jar grm --genotypes examples/grm/dosages.tsv --maf 0 --call-rate 0.95 --block-size 2 --backend cpu --out build/grm-tutorial/strict.tsv
```

Now v1 is excluded too, leaving two variants. The first diagonal becomes `2/3`
and `K(a,b)` becomes `2/3`. Filter changes alter the estimator's marker set;
they are not merely a speed control. Changing only `--block-size` preserves the
estimator, up to floating-point summation differences. It bounds genotype memory
without changing the matrix's sample dimension.

## Step 5: construct from VCF and fit a mixed model

Run this small example from the repository root, with fresh output paths:

```shell
java -jar build/cli/jlinalg-0.3.5.jar grm --genotypes examples/rare-meta/cohort-a.vcf --maf 0.01 --call-rate 0.95 --block-size 256 --backend cpu --out build/grm-demo/cohort.tsv
java -jar build/cli/jlinalg-0.3.5.jar --pheno examples/rare-meta/cohort-a.tsv --id sample --formula "trait ~ 1" --grm build/grm-demo/cohort.tsv --backend cpu --out build/grm-demo/model.tsv
```

The six-person, two-variant fixture demonstrates file interoperability; it is
too small for meaningful relatedness estimation. For an analysis, supply a
prespecified set of quality-controlled, LD-pruned diploid variants. LD pruning,
ancestry adjustment, sample selection, and leave-one-chromosome-out (LOCO) GRMs
are not performed automatically. Construct each desired subset separately.

## Inputs and options

`--genotypes` accepts VCF, VCF.gz/VCF.bgz, BCF, BGEN layout 2, or a plain CSV/TSV
matrix with variants in rows and samples in columns. Format follows the suffix.
Delimited input can have `id,sample1,sample2,...` or
`id,chromosome,position,ref,alt,sample1,...` headers, with commas replaced by tabs
for TSV. Values are alternate-allele dosages in `[0,2]`; `NA` denotes missing.
All source samples are included, in source order. For BGEN without embedded IDs,
add `--bgen-samples cohort.sample` (Oxford sample file or one ID per line).
VCF/BCF uses the existing additive dosage reader. Supply biallelic diploid data
for this diploid relationship estimator; the command does not infer ploidy corrections.

| Option | Default | Meaning |
|---|---|---|
| `--genotypes FILE` | required | Source genotype file |
| `--out FILE` | required | Labeled `.tsv` or `.csv` GRM |
| `--maf` | `0.01` | Minimum minor allele frequency, in `[0,0.5)` |
| `--call-rate` | `0.95` | Minimum called-sample fraction, in `(0,1]` |
| `--block-size` | `256` | Positive number of source variants per block |
| `--backend` | `cpu` | Compute backend policy; explicit accelerators must be available |
| `--bgen-samples FILE` | none | External sample IDs for BGEN |

The command rejects existing result or log paths. `OUT.log` records UTC start/end,
readable elapsed time, source and format, filters, sample count, considered/used/
excluded variant counts, and selected backend. Errors retain a failed timing log
but do not publish a partial matrix. `grm --help` prints the command syntax.

## Matrix definition and limits

For each retained variant, estimate `p` from called dosages in the source sample.
Set `z_i=(g_i-2p)/sqrt(2p(1-p))`; missing dosages are mean imputed, so their
standardized value is zero. All-missing and monomorphic variants are excluded,
as are variants below the MAF or call-rate cutoff. The matrix is
`K = sum(z z') / number_of_retained_variants`.

This is an additive relationship matrix; kinship coefficients are `K/2`.
The denominator is common to all sample pairs. It is not the pairwise-observed
denominator used by some external GRM implementations. Do not expect equality
with an external tool using different filters, missingness, scaling, or weights.

Genotypes are streamed in blocks and filtered-block sums are divided by the
total retained variant count, including when blocks retain different numbers.
The matrix itself remains dense: one double matrix needs `8*N*N` bytes, with
additional construction copies and block workspace. Output is also quadratic;
the log's matrix-byte count is not a peak-memory estimate. Large sample counts
can exceed heap or Java array limits. No sparse approximation is silently used.

The Java equivalent is
`GenomicRelationshipMatrix.fromSource(source, options, backendPolicy, blockSize)`.
It shares normalization and filters with `fromVariantDosages`. Regression tests
use analytically derived matrix entries, missing calls, excluded/unequal blocks,
CSV/TSV round trips, and a VCF-to-mixed-model CLI run. See the
[mixed-model CLI guide](vignettes/command-line.md) for phenotype/sample alignment,
repeated observations, and existing labeled/GCTA GRM input.

## Java vignette

Run the complete [GrmExample.java](../examples/grm/GrmExample.java) from the
repository root using a JDK and the built JAR:

```shell
java --class-path build/cli/jlinalg-0.3.5.jar examples/grm/GrmExample.java
```

The core API calls are:

```java
var source = VariantSources.open(Path.of("examples/grm/dosages.tsv"));
var grm = GenomicRelationshipMatrix.fromSource(source,
    new GenomicRelationshipOptions(0, 0.5), BackendPolicy.CPU, 2);
System.out.println(grm.variantsUsed()); // 3
System.out.println(grm.relationship("a", "b")); // 4/9
System.out.println(grm.kinshipCoefficient("a", "b")); // 2/9
var component = grm.varianceComponent("genetic");
```

`component` can be supplied to the Java mixed-model APIs. If phenotype rows are
reordered or contain repeated observations, use
`grm.varianceComponent("genetic", observationSampleIds)` to form the correctly
aligned observation covariance. Unknown sample IDs are errors. The CLI's
`--individual-id` provides the corresponding phenotype-to-GRM mapping.

## Troubleshooting and reporting

| Symptom | Check |
|---|---|
| Unknown `grm` command | Build current source; the old v0.3.5 release JAR predates this command. |
| No variants remain | Inspect MAF, call rate, monomorphic/all-missing rows, and dosage scale. Do not loosen QC merely to obtain a matrix. |
| Output exists | Choose another path for both result and log; outputs are protected. |
| Sample matching fails | Compare exact source and phenotype IDs; use `--individual-id` for repeated-observation IDs. |
| Heap/array limit | Reduce sample count or use an appropriate external strategy; smaller genotype blocks do not remove dense GRM storage. |
| External GRM differs | Reconcile sample/variant sets, frequencies, imputation, normalization, and allele/ploidy conventions. |

Record the input sample/variant selection, LD pruning, MAF and call-rate rules,
normalization and missingness, backend, and retained counts alongside the run
log. The toy CLI and Java matrices are checked against analytic fractions, and
the VCF-to-mixed-model example has regression coverage. See
[accuracy and performance](verification-and-performance.md) for wider validation;
no GRM speedup claim follows from this small tutorial.
