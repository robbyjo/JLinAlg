Build a genomic relationship matrix.

Follow a small genotype table through filtering, standardization, labeled output, and mixed-model analysis. Use the CLI or the streaming Java API.

What a GRM represents

A genomic relationship matrix has one row and column per sample. It summarizes similarity in centered, standardized additive genotypes. An LD matrix instead indexes variants. A Gaussian mixed model can use Var(y) = sigma_g² K + sigma_e² I, with variance scales estimated by the model. Constructing K does not itself test association or estimate heritability.

Source-build featureThe grm constructor command is newer than the published v0.3.5 release asset. These examples use a JAR built from current source. All example data are synthetic.

3. Construct and inspect the GRM

This teaching example deliberately permits a call rate of 0.5 and MAF of zero to illustrate a retained missing call. These are not proposed production QC thresholds. Choose a fresh output path for every run.

Construct from dosage TSV
java -jar build/cli/jlinalg-0.3.5.jar grm --genotypes examples/grm/dosages.tsv --maf 0 --call-rate 0.5 --block-size 2 --backend cpu --out build/grm-tutorial/toy.tsv

toy.tsv.log reports 5 considered, 3 used, 2 excluded. The monomorphic variant has no allele variance; the low-call-rate variant has only one of four samples called. At v1, the called mean dosage is 1, so sample d is imputed to 1 and contributes a standardized dosage of zero.

Understand the scaling

For each retained variant, estimate allele frequency p from called dosages. Standardize with z_i = (g_i − 2p) / sqrt(2p(1−p)), setting missing standardized values to zero. Then K = sum(z z′) / retained_variants. All sample pairs share this denominator.

K(a,b)=4/9; the corresponding kinship coefficient is half that, 2/9. Negative off-diagonal values can arise from centering and should not be clipped to zero. Diagonals need not equal one. This tiny example cannot establish pedigree categories or population relatedness cutoffs.

Rows sum to zero because each dosage column was centered on these samples. Singularity of this constructed matrix is expected; a mixed model also includes its residual covariance component. External tools using pairwise-observed denominators or other normalization need not give the same matrix.

4. Compare filtering choices

Require 95% called samples
java -jar build/cli/jlinalg-0.3.5.jar grm --genotypes examples/grm/dosages.tsv --maf 0 --call-rate 0.95 --block-size 2 --backend cpu --out build/grm-tutorial/strict.tsv

Now v1 is excluded too: 2 variants remain. The first diagonal and K(a,b) both become 2/3. Changing filters changes the marker set and therefore the estimator. Changing only --block-size preserves the estimator up to floating-point summation differences.

5. Build from VCF and fit a mixed model

A second checked-in fixture provides six samples, a VCF, and aligned phenotype IDs:

Genotypes → GRM → Gaussian mixed model
java -jar build/cli/jlinalg-0.3.5.jar grm --genotypes examples/rare-meta/cohort-a.vcf --maf 0.01 --call-rate 0.95 --block-size 256 --backend cpu --out build/grm-demo/cohort.tsv
java -jar build/cli/jlinalg-0.3.5.jar --pheno examples/rare-meta/cohort-a.tsv --id sample --formula "trait ~ 1" --grm build/grm-demo/cohort.tsv --backend cpu --out build/grm-demo/model.tsv

The grm subcommand creates the matrix; the --grm analysis option consumes it. The example tests file interoperability, not meaningful relatedness estimation. For real data, prespecify quality-controlled, LD-pruned diploid variants and sample selection. The command does not automatically prune LD, adjust ancestry, or construct leave-one-chromosome-out matrices.

Rows and columns retain source sample IDs. The analysis aligns phenotype IDs to them. For repeated observations, use --individual-id COLUMN to name the phenotype column containing the GRM individual ID. See GRM-adjusted scans and mixed-model inference.

Java vignette

The complete GrmExample.java reproduces the four-sample matrix and prints counts, relationships, and kinship.

Run with a JDK
java --class-path build/cli/jlinalg-0.3.5.jar examples/grm/GrmExample.java
Streaming Java API
var source = VariantSources.open(Path.of("examples/grm/dosages.tsv"));
var grm = GenomicRelationshipMatrix.fromSource(source,
    new GenomicRelationshipOptions(0, 0.5), BackendPolicy.CPU, 2);
System.out.println(grm.variantsUsed()); // 3
System.out.println(grm.relationship("a", "b")); // 4/9
System.out.println(grm.kinshipCoefficient("a", "b")); // 2/9
var component = grm.varianceComponent("genetic");

Supply component to a Java mixed-model fit. For repeated or reordered phenotype rows, use grm.varianceComponent("genetic", observationSampleIds). Unknown sample IDs fail explicitly. The file and array builders share the same filters and normalization.

Inputs, options, and memory

Input formats follow their suffix: VCF, VCF.gz/VCF.bgz, BCF, BGEN layout 2, and plain dosage CSV/TSV. All source samples are included. For BGEN without embedded IDs, supply --bgen-samples cohort.sample using an Oxford sample file or one ID per line. Supply biallelic diploid data for this estimator; ploidy corrections are not inferred.

OptionDefaultMeaning
--genotypesrequiredSource genotype file
--outrequiredLabeled .tsv or .csv matrix
--maf0.01Minimum minor allele frequency, [0,0.5)
--call-rate0.95Minimum called fraction, (0,1]
--block-size256Source variants read per block
--backendcpuCompute policy; explicit accelerators must be available
--bgen-samplesnoneExternal BGEN sample IDs

Genotype memory scales with block size, but the matrix remains dense. One matrix requires 8 × N × N bytes, plus construction copies and block workspace. For 10,000 samples, one matrix alone is about 0.8 GB; this is not a peak-memory estimate. Smaller blocks do not remove quadratic storage or output size.

Checks and troubleshooting

OUT.log records UTC start/end, human-readable elapsed time, filters, sample and variant counts, normalization, and backend. Existing results or logs are protected. Failed construction does not publish a partial matrix.

Record sample/marker selection, LD pruning, filtering, normalization, missingness, and the run log with the analysis. The toy matrix is checked against analytic fractions; the VCF-to-mixed-model path has regression coverage. See numerical validation and the complete source guide. This example does not establish a GRM speedup.
