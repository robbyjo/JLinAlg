Start with one phenotype. Build toward xWAS.

A gentle executable-JAR workflow for OLS, exact REML, numeric omics, common and rare variants, pedigree, GLM/GLMM, survival, and regularization.

No Java code is requiredReplace jlinalg-<version>.jar with the downloaded filename. Start a new analysis with --dry-run; use --explain to print routing and continue fitting.

1. Begin with a phenotype file

A phenotype CSV/TSV has one observation per row. The --id column must be unique and later matches omics sample headers.

sample_id,BMI,Sex,Age,clinic
S001,24.8,F,52,A
S002,31.1,M,60,A
S003,27.5,F,47,B
S004,29.0,M,55,B

Phenotype-only OLS

OLS
java -jar jlinalg-<version>.jar --pheno phenotype.csv --id sample_id \
  --formula "BMI ~ Sex + Age" --model ols --out bmi-ols.csv

Rows missing BMI, Sex, or Age are omitted jointly and counted. A .csv result is comma-separated; .tsv and other suffixes use tabs. The run also writes bmi-ols.csv.log and bmi-ols.csv.manifest.json.

Phenotype-only REML

Exact mixed model
java -jar jlinalg-<version>.jar --pheno phenotype.csv --id sample_id \
  --formula "BMI ~ Sex + Age + (1|clinic)" --model lmm \
  --variance-components refit --df satterth --out bmi-clinic-reml.csv

This is a likelihood-based Gaussian mixed model with variance components estimated by REML, not P3D/EMMAX. --df kr requests Kenward-Roger inference.

2. Add numeric omics

Expression, methylation, protein, and generic numeric matrices are feature-by-sample. The first column is the feature ID; every remaining header is a sample ID.

gene_id,S001,S002,S003,S004
GENE_A,5.2,5.7,4.9,5.1
GENE_B,2.0,2.4,2.2,NA

JLinAlg intersects and reorders omics and phenotype IDs automatically and reports every alignment count.

Omics OLS
java -jar jlinalg-<version>.jar --pheno phenotype.csv --omics expression.csv \
  --id sample_id --omics-type expression \
  --formula "BMI ~ Sex + Age + <omics>" --model ols \
  --transform "<omics> = winsor_mad(k=4) | zscore()" \
  --threads 8 --block-size auto --out bmi-expression-ols.csv

Each feature replaces <omics>. Filtering and alignment occur before row-wise transformation; missing feature values are mean-imputed for the fit. Annotation can be appended with --annot genes.tsv --annot-id gene_id --annot-cols symbol,chr.

Omics exact REML
java -jar jlinalg-<version>.jar --pheno phenotype.csv --omics expression.csv \
  --id sample_id --omics-type expression \
  --formula "BMI ~ Sex + Age + <omics> + (1|clinic)" \
  --model lmm --variance-components refit --df satterth \
  --transform "<omics> = winsor_mad(k=4)" --out bmi-expression-reml.csv

For non-genotype omics, --variance-components auto also selects an exact per-feature lmer-like REML refit.

3. Common-variant GWAS

Accepted inputs are VCF, VCF.gz, BCF, BGEN layout 2, and additive-dosage CSV/TSV. VCF/BCF prefers FORMAT/DS and falls back to GT; multiallelic records produce one row per ALT. BGEN supports layout-2 zlib, zstd, or uncompressed blocks; add --sample-file when IDs are external.

id,chromosome,position,ref,alt,S001,S002,S003,S004
rs100,1,101001,A,G,0,1,2,1

A compact delimited matrix may contain only id then sample columns. Dosages are ALT counts in [0,2]; blank, ., NA, N/A, null, and NaN mean missing. Set --omics-type gwas if IDs do not make a delimited genotype file recognizable.

Common variants
java -jar jlinalg-<version>.jar --pheno phenotype.csv --omics cohort.vcf.gz \
  --id sample_id --formula "BMI ~ Sex + Age + PC1 + PC2 + <omics>" \
  --min-maf 0.01 --min-mac 20 --max-marker-missing 0.02 --min-info 0.8 \
  --threads 16 --block-size auto --out bmi-gwas.csv

Excluded variants remain auditable with status=filtered and a reason. Add a labeled dense GRM or GCTA prefix for a genotype LMM. That high-throughput genotype path uses one REML null model and P3D/EMMAX score tests; this is intentionally different from numeric-omics per-feature REML.

4. Rare-variant GWAS

For a single-marker rare scan, add an upper MAF or MAC threshold:

Rare single variants
java -jar jlinalg-<version>.jar --pheno phenotype.csv --omics cohort.bgen \
  --sample-file cohort.sample --id sample_id --omics-type gwas \
  --formula "BMI ~ Sex + Age + PC1 + PC2 + <omics>" \
  --max-maf 0.01 --min-mac 3 --max-mac 40 \
  --max-marker-missing 0.02 --out bmi-rare-single-variant.tsv
Single marker is not a set testJLinAlg implements Burden, SKAT, and SKAT-O in the Java API, but gene/set-membership CLI input is not yet exposed. Do not label this upper-MAF scan as SKAT or a gene-based result.

5. Pedigree, one identifier at a time

There may be three IDs: an omics ID for a measured sample, a repeatable subject ID for an individual, and the pedigree ID that names that subject in the ancestry file.

The phenotype file contains both omics and subject IDs:

omics_id,subject_id,BMI,Sex,Age,visit
OM9001,1001,24.8,F,52,1
OM9002,1002,31.1,M,60,1
OM9003,1003,27.5,F,28,1
OM9004,1003,28.0,F,30,2
OM9005,9009,26.2,M,44,1

The omics matrix headers are OM9001 through OM9005, so --id omics_id. The pedigree file names subjects:

family_id,member_id,parent1_id,parent2_id
F10,1001,0,0
F10,1002,0,0
F10,1003,1001,1002
  • --individual-id subject_id chooses the phenotype-to-pedigree key.
  • --pedigree-id member_id identifies the member row.
  • --sire-id parent1_id and --dam-id parent2_id identify the two parents; the historical option names remain.
  • --pedigree-family-id family_id is optional and qualifies IDs that repeat between families.
Pedigree omics REML
java -jar jlinalg-<version>.jar --pheno phenotype.csv --omics expression.csv \
  --id omics_id --individual-id subject_id \
  --formula "BMI ~ Sex + Age + <omics> + (1|subject_id)" \
  --pedigree pedigree.csv --pedigree-id member_id \
  --sire-id parent1_id --dam-id parent2_id \
  --out bmi-pedigree-expression.csv

The pedigree term must use the phenotype matching-column name, (1|subject_id), not the omics ID or the pedigree file's column name. Blank, NA, 0, ., and -9 parents mean unknown. Pedigree members without phenotypes remain useful ancestors.

Subject 9009 is absent from this pedigree, so JLinAlg adds it as an unrelated singleton and reports it on screen, in the log, and in the manifest. Repeated observations with the same absent subject ID share one singleton family and random effect.

Family-qualified IDsWhen --pedigree-family-id is used, known phenotype IDs must be written as family_id:member_id, such as F10:1003. Raw 1003 is a distinct ID and becomes a singleton. Omit the family option when member IDs are already globally unique.

6. GLM and GLMM

Use --family binomial for a binary response, poisson for counts, and gamma for positive continuous responses. Gaussian is the default.

Binomial GLM
java -jar jlinalg-<version>.jar --pheno phenotype.csv --omics expression.csv \
  --id omics_id --formula "case_status ~ Sex + Age + <omics>" \
  --family binomial --case-value case --control-value control \
  --out disease-expression.csv

Without a random effect this is a GLM. Add (1|clinic), a GRM, or a matching pedigree term for a first-order Laplace, glmer-like GLMM. Use --link only to override a supported family default. Genotype Laplace-GLMM scans are not currently exposed.

Pedigree binomial GLMM
java -jar jlinalg-<version>.jar --pheno phenotype.csv --omics expression.csv \
  --id omics_id --individual-id subject_id \
  --formula "case_status ~ Sex + Age + <omics> + (1|subject_id)" \
  --family binomial --case-value case --control-value control \
  --pedigree pedigree.csv --pedigree-id member_id \
  --sire-id parent1_id --dam-id parent2_id \
  --out disease-pedigree-expression.csv

7. Cox survival analysis

The phenotype needs follow-up time and an event flag. In Surv(time,event), event zero is censored and one is observed.

Right-censored Cox
java -jar jlinalg-<version>.jar --pheno survival.csv --id sample_id \
  --formula "Surv(followup,event) ~ Sex + Age" \
  --model cox --ties efron --out survival-cox.csv

Add a GRM and --individual-id for Gaussian kinship frailty. Streamed omics Cox, start-stop data, formula frailty, and pedigree-correlated Cox remain Java-API features.

8. Ridge, lasso, and elastic net

Penalized regression consumes a numeric observation-by-column CSV/TSV. Predictors are standardized and an intercept is fitted by default.

Regularized Gaussian models
java -jar jlinalg-<version>.jar penalized-regression --input predictors.csv \
  --response y --predictors x1,x2,x3 --model ridge \
  --lambda-grid 10,3,1,0.3,0.1 --cv-folds 5 --out ridge.tsv

java -jar jlinalg-<version>.jar penalized-regression --input predictors.csv \
  --response y --predictors x1,x2,x3 --model lasso \
  --lambda-grid 1,0.3,0.1,0.03,0.01 --cv-folds 5 --out lasso.tsv

java -jar jlinalg-<version>.jar penalized-regression --input predictors.csv \
  --response y --predictors x1,x2,x3 --model elastic-net --alpha 0.5 \
  --lambda-grid 1,0.3,0.1,0.03,0.01 --cv-folds 5 --out elastic-net.tsv

Ridge fixes alpha to 0, lasso fixes it to 1, and elastic net uses the supplied alpha. Use --no-standardize and --no-intercept deliberately. Classical p-values are not emitted for penalized coefficients because penalty selection and post-selection inference are separate tasks.
