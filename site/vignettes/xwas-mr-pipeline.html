Clump once. Scan every phenotype.

A command-line workflow for bounded, parallel Mendelian-randomization screens across many molecular exposures and cardiovascular, kidney, lung, or other phenotype families.

Designed for two-level scansEach exposure keeps one already-clumped instrument set. JLinAlg indexes each outcome once, evaluates the full exposure-by-phenotype grid, and reserves expensive sensitivity analyses for threshold-passing pairs.

The end-to-end workflow

  1. Download an ancestry-matched LD panel and record its manifest.
  2. Search public GWAS results or format custom exposure summary statistics.
  3. Clump each exposure once with the chosen LD threshold and window.
  4. Combine clumped exposures and all outcomes into two long-format tables.
  5. Run mr-xwas, then inspect retained hits, failures, and multiplicity.

The single-outcome MR vignette explains harmonization and estimator interpretation. This page concentrates on the high-throughput command and its operational safeguards.

Run the multi-phenotype CLI

Bounded parallel xWAS MR
java -jar jlinalg-<version>.jar mr-xwas \
  --exposure molecular-traits.clumped.tsv \
  --outcome phenotypes.tsv.gz \
  --output xwas-mr-results.tsv \
  --p-threshold 5e-8 \
  --threads 8 \
  --pair-block-size 256

--threads bounds worker concurrency. --pair-block-size bounds the number of exposure-outcome results held in one work block; it is a memory control, not a statistical batch. Start around four to thirty-two pairs per worker and profile representative data.

Use long-format, clumped inputs

Every exposure row requires a SNP, beta, standard error, effect allele, other allele, and exposure ID. Outcome rows require the equivalent outcome fields and an outcome ID. Effect-allele frequency is optional but improves palindromic-variant harmonization.

Representative columns
SNP  beta.exposure  se.exposure  effect_allele.exposure
other_allele.exposure  eaf.exposure  id.exposure

SNP  beta.outcome  se.outcome  effect_allele.outcome
other_allele.outcome  eaf.outcome  id.outcome  category

Common TwoSampleMR-style names are detected automatically. Use --exposure-id-column or --outcome-id-column for custom identifiers. The optional category or phenotype_category column carries labels such as cardiovascular, kidney-risk-factor, or lung into the results. CSV, TSV, and gzip-compressed inputs and outputs are supported.

Do not clump inside the phenotype loopReclump only when the exposure candidates, ancestry panel, LD build, window, or r-squared threshold changes. Outcome selection does not change an exposure instrument set.

Choose one threshold scale

  • --p-threshold 5e-8 retains p ≤ 5×10−8.
  • --log10-p-threshold -7.30103 retains log10(p) ≤ −7.30103.
  • --negative-log10-p-threshold 7.30103 retains −log10(p) ≥ 7.30103.

Exactly one representation is required. Multiplicative-random IVW is the default screen; use --screen-method fixed for fixed-effect IVW. Correct across the complete prespecified exposure-by-outcome family. Applying BH only after discarding nominally nonsignificant rows is not valid FDR control.

Understand the fast path

The pipeline indexes outcomes by SNP, looks up only each exposure's clumped variants, harmonizes alleles, and runs the selected IVW screen. It processes bounded blocks in parallel and merges results in exposure-major, outcome-major order, so output remains deterministic for fixed inputs, options, and seed.

Only threshold-passing pairs enter the full diagnostic path. Pairs with fewer than three harmonized instruments are counted separately; a downstream diagnostic failure is written with its exposure and outcome IDs instead of terminating the complete scan.

Read results and diagnostics

The primary table reports screening beta, SE, statistic, p on three scales, confidence limits, Cochran Q, heterogeneity p-value, I², mean F, MR-Egger slope and intercept, I²GX, weighted-median estimates, harmonization exclusions, and warnings. A sibling failures table is always produced; choose its location with --failures FILE.

For retained hits, interpret heterogeneity, Egger intercept, instrument strength, and leave-one-out behavior together. Run Steiger directionality and additional robust tests as follow-up analyses; the batch table does not compute them automatically. Use the exported estimates with R, Python, or another plotting tool for forest, funnel, scatter, and leave-one-out figures. Two-way MR is two prespecified runs with exposure and outcome roles reversed, independently selected instruments, and direction-specific harmonization.

Reproduce the benchmark

The checked-in benchmark evaluates 300 exposures against 150 outcomes with 10 already-clumped instruments each: 45,000 IVW pairs. Against an equivalent base-R nested loop, the measured median throughput was 2.20× faster with one Java thread and 5.92× faster with eight threads. Across the first 25 pairs, maximum absolute discrepancies were below 5.6×10−16 for estimates, uncertainty, p-values, Q, and heterogeneity measures.

Java benchmark
./gradlew benchmarkXwasMr

Benchmark scopeThe timing compares the dominant all-pairs multiplicative-random IVW screen after data preparation. It does not claim an end-to-end speedup over TwoSampleMR, and full hit-only bootstrap diagnostics are intentionally outside the timed kernel.

Keep the run auditable

  • Record LD panel, population, genome build, window, r² threshold, and absent variants.
  • Save input checksums, CLI version, threshold, screen method, thread count, block size, confidence level, bootstrap count, and seed.
  • Report total, analyzable, below-threshold, insufficient-instrument, failed, and retained pair counts.
  • Define phenotype families and the multiple-testing strategy before inspecting hits.
