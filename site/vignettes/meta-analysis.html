Analyze separate cohort files from the CLI

Source builds after v0.3.5 provide meta-analysis and meta-regression. Supply repeated --cohort NAME=FILE arguments in the desired cohort order. Unsorted TSV/CSV files, including gzip, are joined by feature ID using disk sorting.

java -jar build/cli/jlinalg-0.3.5.jar meta-analysis --cohort c1=cohort1.tsv --cohort c2=cohort2.tsv --model random --min-cohorts 1 --out meta.tsv
java -jar build/cli/jlinalg-0.3.5.jar meta-regression --cohort c1=cohort1.tsv --cohort c2=cohort2.tsv --cohort c3=cohort3.tsv --moderator-file moderators.tsv --moderators age --model fixed --out regression.tsv

Default input columns are feature_id, beta, and se; override them with --id-column, --effect-column, and --se-column. Effects must already share units and allele orientation. The moderator table has a cohort column and numeric moderator columns.

The direction ++--?- means positive effects in cohorts 1–2, negative effects in 3–4 and 6, and missing cohort 5. Exactly zero effects use 0. The default minimum is one: single-cohort rows pass through with normal inference and unavailable heterogeneity; excluded rows retain an explicit status. Regression additionally requires more complete cohorts than coefficients and a full-rank design.

Ordinary fits use primitive-array batches, with --block-rows, --sort-chunk-rows, and --threads controls. Meta-regression uses a primitive-array API and serial CPU fits. See the six-cohort tutorial and R validation and allocation benchmark. Existing outputs are protected, and the log records cohort order.

Omics example: gene expression across cohorts

The checked-in synthetic files contain log2 expression fold changes and SEs for the same case/control contrast in three independent cohorts. Rows have different orders and cohort coverage. Use consistent gene identifiers and effect units; correct for testing many features downstream.

Build the current source with ./gradlew executableJar (Windows: .\gradlew.bat executableJar), then run from the repository root with fresh output paths:

java -jar build/cli/jlinalg-0.3.5.jar meta-analysis --cohort A=examples/meta-analysis/omics/cohort-a.tsv --cohort B=examples/meta-analysis/omics/cohort-b.tsv --cohort C=examples/meta-analysis/omics/cohort-c.tsv --model fixed --min-cohorts 2 --out build/omics-meta/fixed.tsv
java -jar build/cli/jlinalg-0.3.5.jar meta-analysis --cohort A=examples/meta-analysis/omics/cohort-a.tsv --cohort B=examples/meta-analysis/omics/cohort-b.tsv --cohort C=examples/meta-analysis/omics/cohort-c.tsv --model random --tau-estimator reml --min-cohorts 2 --out build/omics-meta/random.tsv

Directions are +++, ---, and +??. Gene C is retained as below_min_cohorts with unavailable estimates. The default minimum of one instead passes through its single-cohort estimate. Each output has a timing log. Complete omics vignette and Java array example.

Rare-variant meta-analysis in Java and the CLI

The source-built executable also provides rare-score for cohort score/covariance export and rare-meta for single-variant, equal/weighted burden, SKAT, and SKAT-O meta-analysis. These workflows combine aligned variant scores and covariance; per-cohort SKAT p-values alone are insufficient.

Follow the complete rare-variant CLI example to generate the sample cohort files, then run all selected tests:

java -jar build/cli/jlinalg-0.3.5.jar rare-meta --cohorts examples/rare-meta/cohorts.tsv --genome-build GRCh38 --groups examples/rare-meta/groups.txt --test single,burden,skat,skat-o --weights equal --maf 0.5 --cohort-results --out build/rare-demo/selected

The sample has six people per cohort; --maf 0.5 retains its variants for illustration. Choose weights, masks, and thresholds for the research question. Test-specific output files contain signed beta/SE for burden and quadratic or adjusted probabilities for SKAT/SKAT-O. Default SKAT-O simulation cannot resolve genome-wide small p-values.

The rare-variant Java example demonstrates the same tests with ScoreMetaAnalysis and SummarySetTests and includes a runnable source file. Current scope is independent cohorts and quantitative-trait score summaries; the built-in exporter supports unrelated Gaussian models and GRM-adjusted Gaussian REML models.

Define study effects

Effect plus sampling SE
List<MetaStudy> studies = List.of(
    new MetaStudy("A", .20, .10),
    new MetaStudy("B", .50, .20),
    new MetaStudy("C", .10, .15),
    new MetaStudy("D", .70, .25));

The last field is a standard error, not a variance. Log-transform ratios before pooling and back-transform only for presentation.

Fit a fixed-effect model

Common pooled effect
MetaAnalysisResult fixed = MetaAnalysis.fit(
    studies, MetaAnalysisOptions.fixedEffect(),
    BackendPolicy.PREFERRED);

System.out.printf(
    "beta=%g se=%g p=%g Q=%g I2=%g%n",
    fixed.pooledEffectSize(), fixed.standardError(),
    fixed.pValue(), fixed.cochranQ(),
    fixed.iSquared());

Cochran Q and its p-value test excess dispersion. I² and H² summarize heterogeneity; a fixed model has no random-effects prediction interval.

Fit random effects with REML

REML plus modified Knapp–Hartung
MetaAnalysisOptions options =
    MetaAnalysisOptions.builder()
        .method(MetaAnalysisMethod.RANDOM_EFFECT)
        .tauSquaredEstimator(
            TauSquaredEstimator.REML)
        .inferenceMethod(
            MetaInferenceMethod.MODIFIED_HARTUNG_KNAPP)
        .build();

MetaAnalysisResult random = MetaAnalysis.fit(
    studies, options, BackendPolicy.PREFERRED);

Alternatives are DerSimonian–Laird and Paule–Mandel. Report tau²/tau and the prediction interval. Modified Knapp–Hartung never makes the model-based SE smaller.

Explain heterogeneity with moderators

Two-moderator meta-regression
double[][] moderators = {
    {-1, 0}, {0, 1}, {1, 0}, {2, 1}
};
MetaRegressionResult regression =
    MetaRegression.fit(
        studies, moderators,
        List.of("dose", "highRisk"), true,
        options, BackendPolicy.PREFERRED);

System.out.println(regression.moderatorQ());
System.out.println(regression.residualQ());
System.out.println(
    regression.heterogeneityRSquared());

Do not add an intercept column when includeIntercept=true. QM is the omnibus moderator Wald test; QE tests residual heterogeneity. Heterogeneity R² is reduction in tau²—not ordinary variance explained.

Independence assumptionThe first engine assumes independent study estimates. It does not silently provide cluster-robust or multilevel correlated-effect meta-analysis.

Correlated effects and multilevel moderators

MetaMultilevelRegression jointly estimates ML/REML random-moderator covariance over a full sampling covariance matrix. MetaClusterRobust supports CR0, CR1 variants, and CR2 with coefficient-specific Satterthwaite tests. Independent clusters must be genuinely independent, and singular CR2 residual blocks are rejected.

Bias diagnostics and effect sizes

MetaBiasCorrections supplies PET/PEESE and iterative L0/R0/Q0 trim-and-fill. MetaEffectSizes constructs mean differences, Hedges g, log odds/risk ratios, and Fisher-z effects. The Hedges correction is stable for large degrees of freedom. These methods are checked against metafor and clubSandwich; publication diagnostics cannot establish or remove bias. Advanced rare-variant analyses

Choose vt for an adaptive MAF-threshold burden search; het-skat or het-skat-o to allow variant effects to differ between cohorts; and burden-fixed or burden-random for scalar cohort burden effects. Scalar fits require complete, comparable burden masks. Kernel tests do not produce signed effect estimates. VT's selected beta and SE are descriptive after selection; its adjusted p accounts for the threshold search.

java -jar build/cli/jlinalg-0.3.5.jar rare-meta --cohorts examples/rare-meta/cohorts.tsv --genome-build GRCh38 --groups examples/rare-meta/groups.txt --test burden,vt,het-skat,het-skat-o,burden-random --weights equal --maf 0.5 --leave-variant-out --leave-cohort-out --threads 2 --out build/rare-demo/advanced

Leave-out rows identify the omitted variant or cohort in scope, retain original weights, and recalibrate each reduced test. Conditional analysis instead adjusts scores and covariance in each cohort before pooling. It requires conditioning variants and their cross-covariances, with an explicit error or whole-cohort exclusion policy for missing conditioning information.

java -jar build/cli/jlinalg-0.3.5.jar rare-meta --cohorts examples/rare-meta/cohorts.tsv --genome-build GRCh38 --groups examples/rare-meta/conditional-groups.txt --condition examples/rare-meta/conditions.txt --test burden,skat-o --weights equal --maf 0.5 --skato-calibration deterministic --out build/rare-demo/conditional

The deterministic SKAT-O option uses conditional noncentral Gaussian integration, with a relative quadrature tolerance of 1e-6 and explicit convergence failures. It has independently checked rare-tail examples; default simulation retains finite Monte Carlo resolution. Every group run writes a QC manifest. Related-sample score export accepts rare-score --grm; see the GRM construction tutorial.

The complete advanced tutorial explains hypotheses, output fields, calibration limits, missingness, concurrency and cache budgets. Run the advanced Java example and consult the numerical validation and dense-block benchmarks.
