From GWAS download to MR results.

A file-by-file workflow for public or custom instruments, ancestry-matched LD clumping, automatic allele harmonization, diagnostics, and auditable outputs.

Design firstRecord the exposure, outcome, units, ancestry, genome build, covariates, sample sizes, overlap, and licenses before downloading data. Exposure p-values select instruments; outcome p-values must not.
Shell syntaxWebsite command blocks use the POSIX-shell \ line continuation. In PowerShell replace it with a backtick or put the command on one line.

1. Find a public exposure GWAS

GWAS Catalog
java -jar jlinalg-<version>.jar mr-instruments search \
  --trait "body mass index" --limit 20

java -jar jlinalg-<version>.jar mr-instruments download \
  --study GCST00000000 --out bmi-candidates.tsv --p-threshold 5e-8

Replace the fictitious accession. Review its exact phenotype, ancestry, sample description, genome build, full-summary availability, and license. Downloading selects candidates; it does not establish LD independence.

2. Format your own instruments

A candidate row needs SNP, exposure beta, SE, effect allele, other allele, and p-value. EAF is optional but strongly recommended. Normalized output columns are:

Phenotype SNP beta se eaf effect_allele other_allele pval
units ncase ncontrol samplesize gene

CSV, TSV, and gzip-compressed forms are accepted. Common names are detected. For unusual columns, map canonical target names to source names:

Custom GWAS/QTL
java -jar jlinalg-<version>.jar mr-instruments format \
  --input my-exposure.csv.gz --out exposure-candidates.tsv \
  --trait "LDL cholesterol" --p-threshold 5e-8 \
  --map SNP=MarkerName,beta=Effect,se=StdErr,eaf=Freq1,effect_allele=Allele1,other_allele=Allele2,pval=Pvalue

The direction is TARGET=SOURCE. Add --effect-scale odds-ratio or hazard-ratio when Effect is a ratio; JLinAlg converts it to a log effect. A list containing only rsIDs is insufficient: join exposure beta, SE, alleles, and preferably EAF first.

3. Install an ancestry-matched LD panel

LD reference
java -jar jlinalg-<version>.jar ld-db list
java -jar jlinalg-<version>.jar ld-db download \
  --database 1000g-phase3 --location reference/1000g-phase3

The package offers AFR, AMR, EAS, EUR, and SAS panels. Match the exposure study; EUR being the default is not scientific justification.

4. LD-clump the exposure

Independent instruments
java -jar jlinalg-<version>.jar clump \
  --database reference/1000g-phase3 --population EUR \
  --instrument exposure-candidates.tsv --clump-kb 10000 \
  --ld-threshold 0.001 --p-threshold 1 --output exposure-clumped.tsv

The output preserves original columns and order. Variants absent from the panel are excluded; large losses suggest a build, ancestry, or identifier mismatch. Use --snp-column, --pval-column, or --id-column for unusual files. Multiple exposure groups are clumped independently.

5. Prepare outcome associations

The outcome needs results for the clumped variants. Normalize it without an outcome-significance filter:

Outcome table
java -jar jlinalg-<version>.jar mr-instruments format \
  --input coronary-disease.tsv.gz --out outcome-mr.tsv \
  --trait "coronary artery disease" --p-threshold 1 \
  --map SNP=variant,beta=log_odds,se=standard_error,eaf=effect_af,effect_allele=effect_allele,other_allele=other_allele,pval=p_value

Resolve genome builds before MR. Allele harmonization is not liftover.

6. Run MR with automatic harmonization

mr-xwas also handles one exposure and one outcome. It groups rows, intersects SNPs, harmonizes alleles, and estimates MR. A threshold of 1 retains the analyzable pair regardless of causal p-value.

One complete CLI MR
java -jar jlinalg-<version>.jar mr-xwas \
  --exposure exposure-clumped.tsv --outcome outcome-mr.tsv \
  --output bmi-cad-mr.tsv --p-threshold 1 \
  --screen-method random --threads 1 \
  --fdr-output bmi-cad-all-pairs.tsv \
  --follow-up-output bmi-cad-follow-up.tsv

Exposure input needs SNP, beta, SE, effect/other allele and id.exposure, gene, or Phenotype. Outcome needs the same association fields and id.outcome or Phenotype. Override custom grouping fields with --exposure-id-column and --outcome-id-column. EAF helps resolve palindromic alleles.

For many traits, combine normalized rows into two long tables, clump each exposure once, increase threads, and set exactly one p, log10(p), or -log10(p) threshold.

7. Read every output

  • bmi-cad-mr.tsv: retained pairs, IVW estimate/SE/p/CI, heterogeneity, mean F, Egger, weighted median, exclusions, and warnings.
  • bmi-cad-mr.failures.tsv: always written; identifies diagnostic failures.
  • bmi-cad-all-pairs.tsv: every successful screen plus threshold_passed and BH fdr_bh over the complete analyzable family.
  • bmi-cad-follow-up.tsv: optional hit-only RAPS, contamination-mixture, and PRESSO-style results.

Pairs with fewer than three harmonized instruments have no full diagnostic fit. Inspect exclusions and failures before treating an empty result as a null finding.

8. If a table is already harmonized

variant_id,beta_exposure,se_exposure,beta_outcome,se_outcome
rs101,0.08,0.02,0.03,0.01
Estimator-only command
java -jar jlinalg-<version>.jar mr-estimate --input harmonized.csv \
  --method all --output mr-estimates.tsv --plot mr-scatter.svg

The output has method, estimate, standard error, causal p-value, confidence limits, and instrument count. mr-estimate assumes outcome effects already point to the exposure effect allele; because its input has no alleles, it cannot detect a flip. Use mr-xwas for separate unharmonized files.

9. Interpretation checklist

  • Interpret strength, heterogeneity, Egger intercept, robust estimates, and leave-one-out behavior together.
  • Record harmonization exclusions and variants missing from the LD panel.
  • Exponentiate only a log-odds or log-hazard outcome estimate and state the exposure unit.
  • Reverse MR is a second prespecified analysis with independently selected instruments.
  • Colocalization tests regional sharing; it does not prove causality.
