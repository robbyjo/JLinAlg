Use the full workflow from one JAR.

Copy complete commands for phenotype-only and omics models, pedigree and GRM matching, genotype scans, survival analysis, and operational controls—without writing Java code.

Progressive tutorialsStart with association from one model to xWAS, or go directly to mediation, Mendelian randomization, SuSiE, or colocalization.
Version availabilityCommands that explicitly name jlinalg-0.3.4.jar work with that release. The mediation, susie, and coloc CLI subcommands, --max-maf/--max-mac, and the corrected phenotype-only preflight require current jlinalg-0.3.5-SNAPSHOT.jar or a later release.
Start with a preflightOn the general --pheno command, --dry-run reads and aligns inputs, selects complete rows, compiles the formula, loads a requested GRM or pedigree, validates the transform, prints the resolved plan, and stops before fitting. Singular --explain prints that plan and continues. Specialized subcommands instead use their own --help.

Keep the three ID layers separate

OptionPurpose
--id SampleNameAlign phenotype observations to omics/genotype sample IDs.
--individual-id sabreidMap phenotype rows to pedigree or GRM members; may repeat and defaults to --id.
--pedigree-id sabreidName the individual column inside the pedigree file; parent columns refer to it.

The pedigree term must match the phenotype mapping column. Therefore --individual-id sabreid requires (1|sabreid). A separate (1|batch) term remains an ordinary independent random intercept.

After alignment and complete-case omission, phenotype individual IDs absent from the pedigree file are retained as unrelated, noninbred singleton families. Repeated observations sharing one missing ID map to the same founder/random effect; different missing IDs remain unrelated. The screen, log, and manifest report singleton-family and singleton-observation counts.

Phenotype-only and numeric omics OLS

Phenotype-only OLS
java -jar jlinalg-0.3.4.jar --pheno phenotype.csv --id SampleName --formula "BMI ~ Sex + Age" --out bmi-coefficients.csv
Expression scan with transform and annotation
java -jar jlinalg-0.3.4.jar --pheno phenotype.csv --omics expression.csv --id SampleName --omics-type expression --formula "BMI ~ Sex + Age + <omics>" --transform "<omics> = winsor_mad(k=4) | zscore()" --annot genes.tsv --annot-id gene_id --annot-cols symbol,chromosome --threads 8 --block-size auto --out bmi-expression.csv

Numeric omics files are feature-by-sample. Phenotype/omics IDs are intersected and reordered automatically. Rows missing any phenotype model variable are omitted; missing values within an omics feature are mean-imputed after transformation. See the transform guide for every stage.

Grouped exact REML

Numeric LMM
java -jar jlinalg-0.3.4.jar --pheno phenotype.csv --omics expression.csv --id SampleName --formula "BMI ~ Sex + Age + <omics> + (1|site)" --variance-components auto --df satterth --out bmi-expression-site.tsv

For numeric omics, auto performs an exact lmer-like REML refit for every feature. It is not P3D/EMMAX.

Pedigree REML and singleton families

Globally unique pedigree IDs
java -jar jlinalg-0.3.4.jar --pheno phenotype.csv --omics expression.csv --id SampleName --individual-id sabreid --formula "BMI ~ Sex + Age + <omics> + (1|sabreid)" --pedigree pedigree.csv --pedigree-id sabreid --sire-id fid --dam-id mid --out bmi-expression-pedigree.csv

The matching (1|sabreid) term uses Henderson's sparse additive relationship inverse. File members without phenotypes remain in the ancestry graph. Missing file IDs become reported singleton families, and repeated rows with the same ID share one founder. Blank, NA, 0, ., and -9 parent values mean unknown.

Pedigree plus independent batch effect
java -jar jlinalg-0.3.4.jar --pheno phenotype.csv --omics expression.csv --id SampleName --individual-id sabreid --formula "BMI ~ Sex + Age + <omics> + (1|sabreid) + (1|batch)" --pedigree pedigree.csv --pedigree-id sabreid --sire-id fid --dam-id mid --out bmi-pedigree-batch.tsv

Family-qualified pedigrees

Use --pedigree-family-id family only when individual IDs repeat between families. JLinAlg qualifies each file member and parent as family:individual. A known phenotype member must use the same key, such as F01:1001, in its --individual-id column.

Qualified known members; unqualified singletons
java -jar jlinalg-0.3.4.jar --pheno phenotype.csv --id SampleName --individual-id pedigree_key --formula "BMI ~ Age + (1|pedigree_key)" --pedigree pedigree.csv --pedigree-family-id family --pedigree-id member --sire-id sire --dam-id dam --out bmi-family-pedigree.tsv

An unqualified phenotype key with no pedigree row is retained as a singleton. Do not use raw 1001 for a known qualified member: it is a distinct ID and is not guessed to mean F01:1001.

GRM-adjusted scans

Labeled or GCTA GRM
java -jar jlinalg-0.3.4.jar --pheno phenotype.csv --omics expression.csv --id SampleName --individual-id IID --formula "BMI ~ Sex + Age + <omics>" --grm cohort --out bmi-expression-grm.tsv

--grm accepts a labeled square CSV/TSV or a GCTA prefix backed by .grm.bin and .grm.id. Numeric features get per-feature REML refits. A GRM and pedigree cannot be combined in one CLI model.

Binary, count, and gamma models

Binary expression scan
java -jar jlinalg-0.3.4.jar --pheno phenotype.csv --omics expression.csv --id SampleName --formula "case_status ~ Sex + Age + <omics>" --family binomial --case-value case --control-value control --out disease-expression.tsv

Add (1|site), a GRM, or a matching pedigree term for per-feature glmer-like Laplace refits. Use --family poisson for counts and --family gamma for positive continuous outcomes. Genotype Laplace GLMM scans are not exposed.

Genotype GWAS and P3D

VCF/BCF/BGEN fixed scan
java -jar jlinalg-0.3.4.jar --pheno phenotype.csv --omics cohort.vcf.gz --id IID --formula "BMI ~ Sex + Age + PC1 + PC2 + <omics>" --min-maf 0.01 --min-mac 20 --max-marker-missing 0.02 --out bmi-gwas.tsv

BCF and biallelic layout-2 BGEN are supported; add --sample-file cohort.sample when BGEN sample IDs are external. Adding a GRM selects genotype LMM null-model P3D/EMMAX. Pedigree genotype scans and per-marker variance-component refits are not available.

Cox and GRM frailty

Right-censored Cox model
java -jar jlinalg-0.3.4.jar --pheno phenotype.csv --id SampleName --formula "Surv(followup,event) ~ Sex + Age" --ties efron --out survival.tsv

Add --grm cohort --individual-id IID for Gaussian kinship frailty. Formula frailty terms and pedigree Cox models exist in the Java API but are not exposed by this general CLI.

Regression-only commands

MR instrument preparation, LD database installation and clumping, MR estimation, and parallel xWAS MR are also CLI-native. Follow the dedicated mediation, MR, SuSiE, and colocalization tutorials and the parallel xWAS MR guide for their complete schemas.

Operational controls

  • Use singular --explain on the general command to print routing and continue fitting; use --dry-run to stop after preflight. A dry run writes the normal log but no result or manifest. Neither switch scans feature rows.
  • Automatic block sizing uses JVM heap headroom and the requested thread count. When memory permits it queues at least two complete worker waves so work stealing can absorb slow chunks at block boundaries. Low heap headroom uses the largest complete wave that fits or safely limits worker capacity; explicit --block-size N remains available.
  • A .csv output is comma-separated; other suffixes are tab-separated.
  • Use --overwrite deliberately. Verified resume of partial output is not available; choose a new output after interruption.
  • Preserve the generated log and manifest with the result table.
