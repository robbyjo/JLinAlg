CLI-only pedigree REML

Match observation and pedigree IDs
java -jar jlinalg-0.3.5.jar --pheno phenotype.csv --omics expression.csv --id SampleName --individual-id sabreid --formula "BMI ~ Sex + Age + <omics> + (1|sabreid)" --pedigree pedigree.csv --pedigree-id sabreid --sire-id fid --dam-id mid --out bmi-pedigree.csv

SampleName aligns phenotype and omics observations; sabreid maps them to pedigree members. An ID truly absent from the pedigree file becomes one unrelated singleton family. Repeated rows sharing that ID remain together under one founder/random effect. At least one aligned ID must match a source pedigree member; zero matches fail rather than producing an all-singleton model. The screen and log report both family and observation counts.

Family-disambiguated pedigree IDs plus batch
java -jar jlinalg-0.3.5.jar --pheno phenotype.csv --omics expression.csv --id SampleName --individual-id pedigree_key --formula "BMI ~ Sex + Age + <omics> + (1|pedigree_key) + (1|Levy_Set)" --pedigree pedigree.csv --pedigree-family-id pedno --pedigree-id sabreid --sire-id fid --dam-id mid --out bmi-qualified-pedigree.csv

--pedigree-family-id pedno disambiguates pedigree member IDs that repeat between families; it does not define relatedness. A globally unique raw phenotype ID resolves automatically, and an exact pedno:sabreid value is also accepted. A duplicated raw ID is ambiguous and fails until qualified. Recursive parent links construct the ancestry graph, so a unique raw parent can connect rows carrying different family labels. A grouping column such as Levy_Set is an ordinary batch effect and belongs in its own formula term, not the pedigree family column.

Build a pedigree

Validated ancestry
Pedigree pedigree = Pedigree.of(List.of(
    PedigreeIndividual.founder("sire"),
    PedigreeIndividual.founder("dam"),
    new PedigreeIndividual(
        "offspring", "sire", "dam")));

double relatedness = pedigree.relationship(
    "sire", "offspring");
double[] inbreeding =
    pedigree.inbreedingCoefficients();

Input order is arbitrary. Named parents must exist, cycles and duplicate IDs fail, and null denotes an unknown unrelated founder source. This matches the pedigreemm hierarchy contract: parent links recursively propagate relationships, inbreeding, and sparse A-inverse contributions across every generation; family labels neither truncate nor create those links.

Fit the dense reference animal model

Animal REML
List<String> animal = List.of(
    "sire", "sire", "dam", "dam",
    "offspring", "offspring");

PedigreeRemlResult fit = PedigreeReml.fit(
    phenotype, fixedDesign, animal, pedigree);

double h2 = fit.heritability();
double blup = fit.breedingValue("offspring");
double reliability = fit.reliability("offspring");
Map<String, Double> modes = fit.ranef();

Observation IDs may repeat; ancestors without phenotypes remain in the prediction system. Results expose fixef, named ranef, varCorr, fitted values, and residual aliases alongside heritability, BLUP, PEV, and reliability.

Simulate and bootstrap the pedigree

Relationship-aware draws
PreparedPedigreeReml prepared =
    PreparedPedigreeReml.of(
        fixedDesign, animal, pedigree);
PedigreeRemlResult fitted =
    prepared.fit(phenotype);

double[][] responses = PedigreeSimulation.simulate(
    prepared, fitted, 100, 42,
    MixedModelSimulationMode.MARGINAL);
GaussianBootstrapResult intervals =
    PedigreeBootstrap.bootstrap(
        prepared, fitted,
        new BootstrapOptions(999, 0.95, 42, 1));

Marginal draws sample breeding values jointly from the fitted numerator-relationship covariance. Conditional draws retain BLUPs. Bootstrap refits reuse the prepared animal model and preserve structured failures.

Use A-inverse directly

Sparse pedigree REML
SparseSymmetricMatrix aInverse =
    pedigree.sparseRelationshipMatrixInverse();

SparsePedigreeRemlResult sparse =
    SparsePedigreeReml.fit(
        phenotype, fixedDesign, animal, pedigree,
        RemlOptions.builder()
            .initialVariances(1, 1).build(),
        BackendPolicy.PREFERRED);

This path never constructs dense A or observation-scale ZAZ′ during variance fitting. Diagonal prediction-error variances are extracted in fixed-size sparse solve batches, with reliabilities for every pedigree member and selected-member lookup by ID.

Combine pedigree and ordinary terms

Animal plus batch
PedigreeRandomEffectTerm additive =
    PedigreeRandomEffectTerm.of(
        "animal", animal, pedigree);
RandomEffectTerm batch =
    RandomEffectTerm.randomIntercept(
        "batch", batchIds);

SparseLinearMixedModelResult combined =
    SparsePedigreeMixedModel.fit(
        phenotype, fixedDesign,
        List.of(additive), List.of(batch),
        RemlOptions.builder()
            .initialVariances(1, 1, 1).build(),
        BackendPolicy.PREFERRED);
Covariance boundaryDiagonal PEV and reliability scale linearly in output size. A full prediction covariance remains intentionally unavailable because its storage is quadratic; request named diagonal uncertainty when a full covariance block is unnecessary.
