Home/Vignettes/CLI colocalization

Ask whether two regional signals are shared.

Fine-map each trait, intersect credible-effect evidence safely, and report signal-level H0-H4 with H4-conditional shared variants.

Version availabilityThe coloc CLI command was added after v0.3.4. Use current jlinalg-0.3.5-SNAPSHOT.jar or a later release; it is not present in the published v0.3.4 JAR.
Colocalization is not MRIt tests whether association signals in a region appear to share a causal variant. It neither estimates nor proves a causal effect between traits.
Shell syntaxWebsite command blocks use the POSIX-shell \ line continuation. In PowerShell replace it with a backtick or put the command on one line.

1. Fine-map both traits

Use the same genome build, explicit allele alignment, a common defensible locus, and an appropriate LD matrix for each trait.

Two converged SuSiE fits
java -jar jlinalg-<version>.jar susie \
  --summary expression-locus.tsv --ld expression-ld.tsv \
  --sample-size 1200 --effects 10 --out expression-susie.tsv

java -jar jlinalg-<version>.jar susie \
  --summary disease-locus.tsv --ld disease-ld.tsv \
  --sample-size 85000 --effects 10 --out disease-susie.tsv

Require convergence in both logs. The inputs below are the generated *.effects.tsv files.

2. Understand the long input

effect_index,variant_id,log_bayes_factor
1,rs1001,15.22
1,rs1002,4.01
1,rs1003,-0.30

A custom CSV/TSV may use aliases effect, SNP/rsid, and lbf/logbf. Every effect within one file must contain the same unique variant set. The two traits may differ: exact variant IDs are intersected in trait-1 order. Coordinates or alleles are never guessed.

3. Run colocalization

Default coloc.susie priors
java -jar jlinalg-<version>.jar coloc \
  --trait1 expression-susie.tsv.effects.tsv \
  --trait2 disease-susie.tsv.effects.tsv \
  --out expression-disease-coloc.csv

Defaults are p1=1e-4, p2=1e-4, p12=5e-6, and minimum common-variant posterior overlap 0.5. Specify sensitivity runs with --trait1-prior, --trait2-prior, --shared-prior, and --minimum-overlap. --no-trim evaluates low-overlap pairs for diagnosis; it does not repair coverage.

4. Read the outputs

  1. The main file has one retained signal pair per row, source effect indices, common count, lead variants, and posterior_h0 through posterior_h4.
  2. OUT.variants.tsv has each common variant's posterior_shared_given_h4 for each pair.
  3. OUT.log records inputs, signal counts, common variants, retained/skipped pairs, priors, overlap control, and paths.

Use --variant-output and --log for explicit names. Output suffix controls delimiter; existing files require --overwrite.

5. Interpret H0-H4

  • H0: neither trait is associated.
  • H1/H2: only trait 1/trait 2 is associated.
  • H3: both are associated with distinct causal variants.
  • H4: both are associated and share a causal variant.

The five values sum to one for a signal pair. The variant posterior is conditional on H4: a 0.90 shared-variant posterior is not an unconditional 90% claim when H4 is 0.05. Report both.

6. Diagnose and vary assumptions

Inspect common variants and skipped pairs. Heavy trimming usually signals mismatched coverage or a signal outside the overlap. Repeat prespecified plausible priors and appropriate LD/locus choices. For an MR/xWAS follow-up, report the MR estimate separately from H3/H4, priors, common count, skipped pairs, and leading conditional-H4 variants.
