Transform each molecular feature deliberately.

Choose a built-in stage, compose stages from left to right, and keep the tested scale explicit in EWAS, TWAS, and PWAS command-line analyses.

Scope--transform applies only to the <omics> term in feature-by-sample CSV or TSV matrices. Genotype transforms are not supported for VCF, BCF, or BGEN inputs.

CLI-only transform quick start

PowerShell · EWAS
java -jar build/cli/jlinalg-0.3.3.jar `
  --omics methylation.tsv `
  --pheno phenotype.tsv `
  --id IID `
  --formula "trait ~ age + sex + <omics>" `
  --transform "<omics> = mvalue(epsilon=1e-6) | zscore()" `
  --out ewas-results.tsv

The omics file has one feature per row and one sample per column. Its first column is the feature ID:

feature_id  S1    S2    S3    S4
cg000001    0.12  0.20  NA    0.85
cg000002    0.44  0.51  0.49  0.55

Read the pipeline syntax

--transform "<omics> = stage(parameters) | next_stage()"

Use the literal target <omics> and quote the complete specification so the shell does not interpret <, >, or |. Whitespace around the target-assignment = and stage separator | is optional; the examples include it to make those boundaries clear. Stages run left to right. JLinAlg aligns sample IDs first, then applies the complete pipeline independently to every feature row; it never pools values across features. Repeating --transform appends stages in command-line order. Omitting the option is equivalent to identity().

Choose a built-in stage

StageOperationContract
identity()Copy without changing values.identity is also accepted.
winsor(p=0.01)Clamp to symmetric empirical quantiles.p means lower p and upper 1-p; linear-interpolation quantiles.
winsor(lower=0.01,upper=0.99)Clamp to separate lower and upper quantiles.Defaults are 0 and 1; require 0 <= lower <= upper <= 1.
winsor_mad(k=4)Clamp to median +/- k * MAD, where MAD = median(abs(x-median)) / qnorm(0.75).k defaults to 4 and must be finite and nonnegative. Missing values do not enter either median; zero MAD leaves the row unchanged. Bare winsor_mad is accepted.
log1p()Compute ln(1+x).Finite values must be greater than -1; log1p is accepted.
log(offset=1)Compute ln(x+offset).Offset must be finite and shifted finite values must be positive.
zscore()Center and divide by the row's sample SD.Requires two varying finite values; zscore and zscore(ddof=1) are aliases.
int()Tie-aware Blom rank inverse-normal transform.Uses average ranks; int and int(method=blom) are aliases.
mvalue(epsilon=1e-6)Clip methylation beta values, then compute base-2 log odds.Inputs in [0,1]; epsilon defaults to 1e-6 and must be in (0,0.5).

Names are case-insensitive. Use the parameter names shown. Custom expression syntax such as expr(...) is deliberately not enabled.

Match the pipeline to the data

Robust median/MAD clipping

--transform "<omics> = winsor_mad(k=4) | zscore()"

Clamp outliers relative to a robust row center and scale, then standardize. This matches R's mad(..., constant = 1/qnorm(0.75), na.rm = TRUE) scaling. A zero raw MAD leaves the row unchanged.

Methylation beta values

--transform "<omics> = mvalue(epsilon=1e-6) | zscore()"

Convert beta values to M values, then report effects per one standard deviation of the transformed feature.

Nonnegative expression measurements

--transform "<omics> = log1p() | zscore()"

Compress a long right tail and standardize. Use log(offset=...) when the required pseudocount is not one.

Protein abundance with outliers

--transform "<omics> = winsor(p=0.01) | int(method=blom)"

Limit extreme observations, then use normal scores. Rank inverse-normalization changes the estimand; choose it as an analysis decision. Adding zscore() after int() is generally redundant.

Asymmetric clipping

--transform "<omics> = winsor(lower=0.005,upper=0.975) | zscore()"

Use separate tails only when that asymmetry is part of the scientific preprocessing rule.

Understand missing values and failures

Blank cells plus ., NA, N/A, null, and NaN are missing. Built-in stages preserve them and calculate row statistics from finite values. After the complete transform pipeline, the CLI mean-imputes remaining missing entries within that transformed feature row.

Domain checks are strict: log1p() rejects -1, log() rejects a nonpositive shifted value, mvalue() rejects values outside [0,1], and zscore() rejects constant rows. A transform-domain error or a row with no finite values stops the run. A feature that passes the transform but is non-estimable after model adjustment uses the normal structured failure output and accounting.

InterpretationCoefficients are on the final transformed scale. Record the exact transform string, input version, and analysis choices with the result manifest and log.

Add a trusted custom stage

Implement OmicsTransformProvider, package it in a JAR, and register its class in META-INF/services/org.jlinalg.pipeline.OmicsTransformProvider. The provider receives named string parameters and must return the same number of sample values.

Custom provider
public final class ScaleTransformProvider
        implements OmicsTransformProvider {
    public String name() { return "scale"; }

    public OmicsTransform create(Map<String, String> parameters) {
        double factor = Double.parseDouble(
            parameters.getOrDefault("factor", "1"));
        return values -> {
            double[] result = values.clone();
            for (int i = 0; i < result.length; i++)
                if (Double.isFinite(result[i])) result[i] *= factor;
            return result;
        };
    }
}

The service file contains the fully qualified provider class, for example example.ScaleTransformProvider. Load and compose it like this:

--transform-plugin transforms.jar \
--transform "<omics> = scale(factor=2) | zscore()"

Plugin JARs execute arbitrary JVM code in the analysis process. Load only artifacts you trust.
