# Exact quantile LP: reference and timing evidence

Measured locally on 2026-09-08. This is an unweighted, unconstrained, dense,
full-column-rank quantile regression LP, not a smoothed approximation. The
existing smoothed `QuantileRegression.fit` is unchanged. `fitExact` delegates
to `QuantileLinearProgram.solve`; the latter also exposes the dual weights and
an optimality certificate. An intercept must be supplied as a design column.

The deterministic Mehrotra predictor-corrector algorithm minimizes
`tau sum(u) + (1-tau) sum(v)`, with `X beta + u - v = y`, `u,v >= 0`.
The dual maximizes `y'z` with `X'z = 0`, `tau-1 <= z <= tau`.
Column/effect scaling and subtraction of an OLS fitted origin improve numeric
range. Each iteration reuses one weighted pivoted QR in its predictor and
corrector steps. Storage is O(n p + p squared), not an n-by-n tableau.
Both scaled LP and reconstructed original-data solutions must pass feasibility,
complementarity and primal-dual-gap checks; the reported objective is always
the actual nonsmoothed pinball sum.

## Accuracy

`ExactQuantileTest` passes seven tests, including 25 frozen `quantreg::rq.fit.br`
fits generated by `src/test/resources/exact-quantile/generate-exact-quantile.R`.
The fixtures cover quantiles .01 through .99, heteroscedastic data, outliers,
no intercept, saturated and perfect fits, ties and nonunique optimal faces.
Only objectives and KKT conditions are required for nonunique coefficients.
Maximum fixture objective difference: **1.3483e-9**.

Additional tests cover deterministic output, defensive dual exports, unchanged
inputs, strict iteration-budget failure, invalid/nonfinite/rank-deficient and
numerically singular inputs, column scales 1e-9 through 1e12, and response
units 1e-9. The small-response fit preserves rescaled coefficients and objective.

Adding 1e8 to a response with an intercept preserves objective within 2.5e-8
and coefficients within 1e-7. However, a double at this magnitude has an ulp
of about 1.49e-8. The reconstructed normalized primal residual is 2.41e-8,
so the default 1e-9 tolerance correctly returns `converged=false`. Explicit
`Options(200, 1e-8)` passes the original-data certificate and independently
checked KKT conditions. This is an explicit caller precision choice; default
certification has not been loosened to conceal the rounding limitation.

## Timings

Each measurement uses the same frozen matrix and tau=.75, 10 warmups and 100
fits, excluding fixture I/O and process startup. R uses matrix-level BR and
Frisch-Newton calls; Java includes its returned diagnostics/certificate and
backend context. Both consume coefficient checksums. R FNB uses eps=1e-9;
default BR is the objective reference. Tolerances are solver-specific, not
identical stopping rules. All Java benchmark fits converge; largest objective
error is 1.596e-9 and coefficient error is 1.468e-8.

| Rows / columns | Java LP ms | R BR ms | R FNB ms |
| --- | ---: | ---: | ---: |
| 256 / 4 | 0.677 | 0.084 | 0.122 |
| 1024 / 6 | 1.818 | 0.692 | 0.631 |
| 4096 / 8 | 9.895 | 7.705 | 3.596 |

R's compiled quantreg routines are faster on these workloads. These are local
wall-clock measurements, not a general performance claim. Exact outputs are
saved in `measured-java.csv` and `measured-r.csv`.

## Reproduction and limits

From the repository root, run the two R scripts with Rscript (on this host,
`C:/Program Files/R/R-4.6.1/bin/Rscript.exe`; elevation is needed to read the
installed user-library dependencies). Both set the project R library first.
The benchmark script is `src/benchmark/r/exact_quantile_benchmark.R 100`.
It regenerates only this uniquely named benchmark resource directory.

Compile `QuantileLinearProgram.java`, `QuantileRegression.java`,
`ExactQuantileTest.java` and `ExactQuantileBenchmark.java` with Java release 17
against the project's main classes, JDistlib and JUnit dependencies. Run
`org.jlinalg.regression.ExactQuantileTest`; then run
`java -Xms256m -Xmx1g -cp <compiled-classpath> org.jlinalg.benchmark.ExactQuantileBenchmark 100`.
The handoff used isolated `build/exact-quantile-classes`, `-Xlint:all -Werror`,
and no global Gradle build.

This is numerical LP optimization, not symbolic/rational exact arithmetic.
There is no coefficient uniqueness guarantee, inference/standard errors,
observation weights, general linear constraints, rank-deficient-design solution,
or sparse/high-dimensional n<p path. Ill-conditioned designs/Newton systems
are rejected explicitly. A finite iteration budget or failed final certificate
returns `converged=false`; nonrepresentable arithmetic throws an exception.
